# The platform's tools

Checks of the platform track (docs/specs/platform.final.md, section 10). Each prints a `FAIL ...` line per problem
and a `RESULT ...` line, and exits 1 on any failure.

What they need:
- the browser checks (`p0.js`, `compare-shots.js`): Playwright with its Chromium (`NODE_PATH=$(npm root -g)`), as
  the regression suite does, and its helpers (`tools/regress/lib.js`, `tools/regress/iphone-audit.js`);
- the stack and the SQL suite: the machine's PostgreSQL 16 server at `/usr/lib/postgresql/16/bin` (or `HS_PG_BIN`),
  run as the `postgres` user on a throwaway folder under `/var/tmp/hs-stack` (or `HS_STACK_DIR`), and one npm
  package, `pg`: run `npm install --prefix tools/platform` once (it lands in `tools/platform/node_modules`, which
  git ignores);
- the shell checks: bash, curl, jq and openssl; `guide-check.sh` also nginx (or its Ubuntu package unpacked
  without installing it: `apt-get download nginx nginx-common`, then `dpkg -x` each into one folder).

No secret is kept anywhere here. The stack makes its JWT secret from random bytes when it starts, keeps it in its
own memory and never writes it; its anon key is worth nothing once it stops. The database has no password at all:
it listens on a socket in its own folder only.

| script | what it does |
| --- | --- |
| `stack.js` | The local stack (10.1): PostgreSQL with `standins.sql`, `deploy/supabase/schema.sql` and `test-clock.sql`; on one port the Supabase address (a stand-in for PostgREST at `/rest/v1/rpc/<fn>` that runs each call as `authenticator` under `set local role anon` or `authenticated` and the JWT's claims, read-only for a stable function, with the role's statement timeout; a stand-in for Auth with settings, authorize with PKCE, callback, token for pkce and refresh_token with rotation, user, logout; CORS as the gateway answers it; by default only what the guide's public name serves is served (Auth's settings, authorize, callback, token for pkce and refresh_token, user to read, logout and health, and `/rest/v1/rpc/hs_`), and `--wide` serves the rest as a bare gateway would, Auth's signup, otp, recover, magiclink, password sign-in and user writes answering 200 as an open Supabase Auth would, doing nothing); a fake OAuth provider at `/provider/` (test people, or one a test picks with `POST /__test/provider {"who": ...}`: `aram`, `bagrat`, `nune`, `fb-noemail`, `discord-unverified`, `cancel`, `error`, `hang`); controls at `/__test/` (`auth` and `rest` `{"mode": "up" | "down" | "hang"}`, `clock` `{"offset": "1 day"}` for the database, `authclock` `{"seconds": N}` for Auth, `expire`, `runback`, `reset`, `settings` (e.g. `mailer_autoconfirm`), `provider`, `redirects`, `narrow`, `admin`, `query`, `state`); and on a second port the game at `/` and `/next/` as the live web root holds it (`index.html` and `og.jpg` only, every other path answered with the page as nginx's `try_files` does), read from disk on every request (`--page=DIR`, `--next=DIR`); a body over 512 KB is answered 413. `node tools/platform/stack.js` prints both addresses, the anon key and a `psql` line; Ctrl+C stops it and removes its database. From a test: `const s = await require("./tools/platform/stack").start({ page })`, then `s.url`, `s.site`, `s.anonKey`, `s.control(name, body)`, `s.query(sql)`, `s.stop()`. For the page under test, `window.__HS_PLATFORM_TEST = { url: s.url, anonKey: s.anonKey }`. |
| `sql-tests.js` | The SQL suite (10.2, with RULINGS S1 to S5 and S8): a fresh database, `schema.sql` run twice, then every rule as a visitor, a player and an admin, called as PostgREST calls (as `authenticator`, a role and the claims set for the transaction, stable functions read-only): structure and grants, every table refused every way, names, saves, rulesets, scores and boards, the daily, analytics and the stats, the purge, read-only functions, account deletion, the size ceiling; then again with `schema-handoff.sql` loaded. About 3 s. `--only=group,...`, `--verbose`, `--keep`. |
| `unit.js` | The pure checks (10.4). Today: the reference arithmetic (`ref.js`: the score, the lost daily, the daily's pick, the name rule) against the spec's numbers, and the stack's PKCE (RFC 7636's vector) and JWT code. The page's own `PF_PURE` block (`sha256`, `pkceChallenge`, `nameCheck`, `inAppUA`, `providersOf`, `signinLine` from P2, the challenge also held to Node's and `crypto.subtle`'s, `Cloud` from P3, `EvQueue` with `evBytes`, `evDevice` and the robot rule from P4 (sizes as the server counts them, the page's limits, batches by bytes, the waits after a failure, three refusals), `scoreOf` from P5, `dailyOf` from P6) is held to the same tables once it exists; until then each is listed as waiting. Under a second. |
| `ref.js` | The reference arithmetic both sides are held to: `scoreOf`, `starsOf`, `boundsOf`, `dailyOf`, `kOf`, `jOf`, `nameClean`, and the shared tables `SCORE_CASES`, `LOST_CASES`, `NAME_CASES`. |
| `curl-session.sh` | A session with curl alone against the stack: sign-in with PKCE through the test provider, `hs_profile_get` and a name; a code used twice, a wrong verifier, a code used after five minutes, a refresh token reused late; then, as a visitor and as a player, every `hs_` table read and every function outside that caller's grants, each refusal shown; and the narrow name serving nothing else (no table, no other function, none of Auth's routes that make accounts or send mail); the stack's controls, its site port (the page and `og.jpg`, nothing else of the repository) and the 413 for a big body. |
| `smoke.js` | The smoke test against the owner's Supabase (10.6): `node tools/platform/smoke.js <address> <anon key>` (or `HS_SMOKE_URL`, `HS_SMOKE_ANON_KEY`). Public values only, nothing stored; it refuses to go on with a service key. 13 checks; check 11 also tries Auth's signup, otp, recover, magiclink, password sign-in and a write to the user; check 12 opens direct connections to 8000 and 8443 (and names 5432 and 6543 when they answer), and says "not answerable from this machine" rather than pass when a direct connection to the address's own port fails here. Against an address on this machine checks 12 and 13 are reported as answerable only by the real Supabase. Uses this machine's `HTTPS_PROXY` for the https requests when one is set. |
| `smoke-local.js` | `smoke.js` against the stack, then against three broken versions of it (auto-confirm on and the whole API served, a demo key, a service key), to show each check can fail. |
| `guide-check.sh` | Runs the guide's `[tried]` commands, read out of `deploy/supabase/README.md` itself, against the stack behind a real nginx carrying the guide's own nginx lines: step 0's greps, step 1's checks (and what the block refuses: other paths, Auth's routes that make accounts or send mail, which the gateway behind it does serve, slipped paths, floods, big bodies; and the page's preflights still pass), step 3's three checks, `schema.sql` again as the SQL editor's role, step 4's check and audit, step 5's smoke test, step 6's sign-in and admin line, step 9's lines. `bash tools/platform/guide-check.sh [path/to/nginx]`. |
| `test-update.sh` | `deploy/update.sh` on throwaway copies (9.3): the live flow byte for byte against today's script (master's `deploy/update.sh`) through every case it knows, the staging channel's cases, the hand-over from the old script to the new, and `bash -n`. `bash tools/platform/test-update.sh [new] [old] [check-page.js]`. About 6 s. |
| `pgtemp-check.js` | A throwaway database never outlives its test: a test that ends without `stop()`, one stopped by SIGTERM or SIGINT, and one killed by SIGKILL whose folder and server the next start sweeps (while a running test's folder is left alone). About 10 s. |
| `pgtemp.js`, `standins.sql`, `test-clock.sql` | The throwaway PostgreSQL; Supabase's roles (`supabase_admin` the superuser, `postgres` not one), API roles, auth schema and default grants; the test clock (`hs_private.now()` plus the setting `hs_test.clock`). Never run either SQL file on the real Supabase. |

| `compare-shots.js` | Two copies of the page photographed by the harness and compared pixel for pixel: the map, Settings (over the map and over a battle), the chronicle, the victory and defeat pages, at 1600x900 (mouse), 1194x834, 667x320 and 375x553 (touch): 40 pairs. `node tools/platform/compare-shots.js <base index.html> [new index.html] [--out=dir]`. A package that must change nothing a player sees ends with every pair the same. About 100 s. |

The harness's own door to the Hall, for photos and for other tracks' tests:

- `?shot=hall` opens the Hall over the map; `&tab=<id>` picks its tab. With no tab in `HALL_TABS` it ends in
  `PHOTO_ERROR`: the Hall does not open empty.
- `&testtab` (with `?shot=...` or `?selftest`) adds a test tab of the harness's own, `&testtab=N` up to six of them
  (ids `test1`, `test2`, ...); `&long` gives each a long list, to see its box scroll. The first has a badge of 3 and
  the second of 1; "Spend one" counts the shown tab's badge down. They exist nowhere but under the harness.
- `?shot=menu&testtab` is the map with the tally as the Hall's door.
