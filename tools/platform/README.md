# The platform's tools

Checks of the platform track (docs/specs/platform.final.md, section 10). Each prints a `FAIL ...` line per problem
and a `RESULT ...` line, and exits 1 on any failure.

What they need:
- the browser checks (`p0.js`, `compare-shots.js`): Playwright with its Chromium (`NODE_PATH=$(npm root -g)`), as
  the regression suite does, and its helpers (`tools/regress/lib.js`, `tools/regress/iphone-audit.js`);
- the stack and the SQL suite: the machine's PostgreSQL 16 server at `/usr/lib/postgresql/16/bin` (or `HS_PG_BIN`),
  run as the `postgres` user on a throwaway folder under `/var/tmp/hs-stack` (or `HS_STACK_DIR`), and one npm
  package, `pg`: run `npm install --prefix tools/platform` once (it lands in `tools/platform/node_modules`, which
  git ignores);
- the shell checks: bash, curl, jq and openssl; `guide-check.sh` also nginx (or its Ubuntu package unpacked
  without installing it: `apt-get download nginx nginx-common`, then `dpkg -x` each into one folder).

No secret is kept anywhere here. The stack makes its JWT secret from random bytes when it starts, keeps it in its
own memory and never writes it; its anon key is worth nothing once it stops. The database has no password at all:
it listens on a socket in its own folder only.

a body over 512 KB is answered 413. `node tools/platform/stack.js` prints both addresses, the anon key and a `psql` line; Ctrl+C stops it and removes its database. | `pgtemp-check.js` | A throwaway database never outlives its test: a test that ends without `stop()`, one stopped by SIGTERM or SIGINT, and one killed by SIGKILL whose folder and server the next start sweeps (while a running test's folder is left alone). About 10 s. |
| `pgtemp.js`, `standins.sql`, `test-clock.sql` | The throwaway PostgreSQL; Supabase's roles (`supabase_admin` the superuser, `postgres` not one), API roles, auth schema (`auth.uid()`, `auth.jwt()`), default grants in public and the global ones, and the neighbours (a table and a function in `public`, `reqstream` and `reqstream_meta`); the test clock (`highland._now()` plus the setting `hs_test.clock`). | `migrate.js` | The migrations' runner: `status`, `up [N]`, `down N --yes`, `regrant`, `--dry-run`, over `--dsn=` or `HS_DB_URL` (the password only in `PGPASSWORD`; a DSN holding one is refused). Each migration in one transaction under an advisory lock, then the lockdown and, from 003 on, 003's grants; as `postgres`, never a superuser; refuses a migration whose file changed since it was applied. Also a library (`migrate({ client, target })`) for the tests. |
| `isolation.js` | The tenants' walls over HTTP through the stand-in for PostgREST with signed tokens: players A and B, an outsider, a visitor, the admin, service_role; every function, every table and view by GET, POST, PATCH and DELETE with the highland profile, the helpers, the profile headers and PGRST106, the preflight, the sign-in's return through `ADDITIONAL_REDIRECT_URLS`, password sessions, account deletion leaving `auth.users` alone. `--attach=HOST:PORT/DB` tries a database already there (the restore rehearsal's copy). About 2 s. |
| `sqlcheck.js` | The static checks of the SQL files: every UPDATE and DELETE has a WHERE (pg-safeupdate), nothing created, granted or dropped outside highland, no CASCADE, search_path pinned on every function. |
| `rehearsal-cluster.js`, `../../deploy/supabase/restore-rehearsal.sh` | The restore rehearsal: a populated database backed up with `pg_dump -n highland`, restored as `postgres` into a fresh database with the stand-ins, regranted, checked, and the isolation tests run on it (and on a second copy left without the regrant, which must fail them). `bash deploy/supabase/restore-rehearsal.sh [FILE.dump]`. The harness's own door to the Hall, for photos and for other tracks' tests:

- `?shot=hall` opens the Hall over the map; `&tab=<id>` picks its tab. With no tab in `HALL_TABS` it ends in
  `PHOTO_ERROR`: the Hall does not open empty.
- `&testtab` (with `?shot=...` or `?selftest`) adds a test tab of the harness's own, `&testtab=N` up to six of them
  (ids `test1`, `test2`, ...); `&long` gives each a long list, to see its box scroll. The first has a badge of 3 and
  the second of 1; "Spend one" counts the shown tab's badge down. They exist nowhere but under the harness.
- `?shot=menu&testtab` is the map with the tally as the Hall's door.
